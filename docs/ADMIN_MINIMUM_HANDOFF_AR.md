## ما تتضمنه النسخة

| المسار | التنفيذ في المصدر |
|---|---|
| الدخول | حساب إداري فعال، متابعة تعطيل الحساب، وخروج يلغي عرض بيانات الجلسة |
| التسجيل | مراجعة الطلب ونسخه ومستنداته؛ اعتماد أو رفض أو طلب استكمال مع سبب وتسجيل القرار |
| الصيدليات | قائمة وبحث وتفاصيل؛ إخفاء وإعادة ظهور بسبب مسجل، بصورة مستقلة عن استقبال الطلبات |
| المستخدمون | عرض البيانات المسموح بها والبحث، دون إجراء حظر |
| الطلبات | متابعة للقراءة فقط، فلاتر الحالة والتاريخ والصيدلية والتأخر، وإظهار تاريخ التأخر |
| التأخر | معالجة الصيدلية 24 ساعة مع استبعاد انتظار العروض الجزئية؛ استلام المستخدم بعد أول جاهزية بـ24 ساعة، دون إلغاء آلي |
| التنبيهات | تأخر المعالجة والاستلام، التسجيلات المعلقة، توقف الاستقبال ونفاد المتاح، وروابط للمصدر |
| الخريطة | مواقع صحيحة فقط، وفلاتر الظهور والاستقبال والتوفر، مع قائمة بديلة |
| الرئيسية والتقارير | مجاميع من المصدر، وفترات 7/30/90/365 يومًا واتجاهات يومية وتوزيع جغرافي وأدوية مطلوبة بصورة مجمعة |
| الإشعارات | المستخدمون أو الصيدليات أو الجميع؛ تأكيد قبل الإرسال، نتائج التسليم، وإعادة المتعثرين فقط |
| التدقيق | المنفذ والوقت والسبب والجهة وحالة القرار وما قبله وبعده |

القوائم الأساسية تستخدم صفحات من 50 سجلًا وبحثًا خادميًا ببداية الاسم أو الكلمة. التوقيت المعروض Africa/Tripoli. السجل القديم الناقص يظهر «غير مسجل»؛ لا تُختلق له بيانات. نتائج إرسال الإشعارات تحتاج تحديث القائمة أثناء المعالجة.

أزيلت من اللوحة إدارة حسابات وأدوار المشرفين، حظر المستخدمين والصيدليات، تعديل استقبال الطلبات، إدارة الشكاوى، تفاصيل المخزون الداخلي، مجموعات المستلمين المخصصة، وحقول الفواتير والعروض في متابعة الطلبات. أزيل تصدير createAdminEmployee من الخلفية؛ إن كانت نسخة منه منشورة سابقًا فحذفها السحابي خطوة تفعيل أدناه.

## ترتيب التفعيل — تنفذه أنت

الواجهة الجديدة تعتمد على وظائف الخلفية الجديدة؛ تشغيل الواجهة وحده لا يكفي. الأوامر التالية للمشروع الحالي `pharma-apps`. لا تستخدم مجلد `functions` القديم داخل الواجهة كمصدر نشر.

### 1. تعيين المسارات والاعتماديات

افتح PowerShell:

```powershell
$adminRoot = 'C:\Users\hp\OneDrive\Desktop\مشروع التخرج\Roshita_Admin_Panel'
$backendRoot = 'C:\Users\hp\StudioProjects\user_application'
$nodeExe = 'C:\Program Files\nodejs\node.exe'
$npmCli = 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js'
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
$firebaseCli = Join-Path $backendRoot 'functions\node_modules\firebase-tools\lib\bin\firebase.js'
```

يلزم Node 24، وحساب Firebase لديه صلاحية المشروع. الاعتماديات موجودة على هذا الجهاز؛ للحزمة المستخرجة أو عند غيابها نفّذ:

```powershell
Set-Location -LiteralPath $adminRoot
& $nodeExe $npmCli ci
if ($LASTEXITCODE -ne 0) { throw 'توقف تثبيت اعتماديات الواجهة' }
Set-Location -LiteralPath (Join-Path $backendRoot 'functions')
& $nodeExe $npmCli ci
if ($LASTEXITCODE -ne 0) { throw 'توقف تثبيت اعتماديات الخلفية' }
```

إعداد Firebase الحالي موجود في المصدر. إذا استعملت `.env` فضع إعداد Web app الصحيح، ولا تنسخ قيم `your_api_key` أو `your_app_id` التجريبية كما هي. يلزم حساب Firebase Auth قائم ووثيقة `adminEmployees/{uid}` بقيمة `isActive: true` للدخول؛ لا توجد شاشة إنشاء مشرفين في النطاق المعتمد.

### 2. أوامر التحقق المتاحة لك

هذه أوامر جاهزة فقط، ولم أشغّلها. لا تبدأ محاكيًا ولا تنشئ بيئة اختبار:

```powershell
Set-Location -LiteralPath $adminRoot
& $nodeExe .\node_modules\vitest\vitest.mjs run
if ($LASTEXITCODE -ne 0) { throw 'فشل تحقق الواجهة؛ احتفظ بالخرج' }
& $nodeExe .\node_modules\vite\bin\vite.js build
if ($LASTEXITCODE -ne 0) { throw 'فشل بناء الواجهة؛ احتفظ بالخرج' }
Set-Location -LiteralPath (Join-Path $backendRoot 'functions')
& $nodeExe $npmCli run verify
if ($LASTEXITCODE -ne 0) { throw 'فشل تحقق الخلفية؛ احتفظ بالخرج' }
```

لتحقق مركز من منطق الحد الأدنى فقط: `node --test .\test\registration-commands.test.js .\test\admin-panel.test.js .\test\export-map.test.js` من مجلد `functions`. نجاح أمر وحده لا يثبت نجاح التكامل أو قبول الشاشة.

### 3. نشر الخلفية والفهارس

هذه الخطوة تغيّر الخدمات السحابية. تنفذها أنت بعد نجاح تحققك؛ أوامر النشر تحفظ شرط `predeploy verify` الموجود في المشروع.

```powershell
Set-Location -LiteralPath $backendRoot
& $nodeExe $firebaseCli login
$deployTargets = @(
  'functions:adminList', 'functions:adminVisibilityCommand', 'functions:adminInsights',
  'functions:registrationCommand', 'functions:executeOrderCommand', 'functions:processOrderDeadlines',
  'functions:adminOrderProjection', 'functions:onOrderCreated', 'functions:onOrderUpdated',
  'functions:adminList_requests', 'functions:adminList_pharmacies', 'functions:adminList_users',
  'functions:adminList_orders', 'functions:adminList_notifications', 'functions:adminList_audit',
  'functions:adminBroadcastCommand', 'functions:sendAdminBroadcast',
  'functions:retryAdminBroadcast', 'functions:recoverAdminBroadcasts',
  'firestore:indexes'
)
& $nodeExe $firebaseCli deploy --only ($deployTargets -join ',') --project pharma-apps
if ($LASTEXITCODE -ne 0) { throw 'توقف نشر الخلفية؛ لا تنتقل للخطوة التالية' }
```

انتظر وصول الفهارس إلى حالة جاهزة في Firebase Console. تحديث `onOrderCreated` و`onOrderUpdated` مطلوب حتى لا تعيد النسخة القديمة كتابة حقول خارج ملخص الإدارة.

### 4. تهيئة القوائم من البيانات الموجودة

التهيئة ضرورية مرة لهذه النسخة، وقابلة للإعادة. تعيد كتابة ملخصات الإدارة وتبني ست قوائم وتزيل إسقاطات السجلات المحذوفة؛ لا تنشئ طلبات أو مستخدمين أو بيانات تجريبية. احتفظ بنسخة الاسترجاع المعتادة قبل تنفيذ ترحيل مشروعك. دخول Firebase CLI وحده لا يوفر بالضرورة اعتماد Admin SDK: استخدم اعتماد المشغّل الموجود لديك (Application Default Credentials). إذا لم يكن مضبوطًا ولديك Google Cloud CLI يمكنك إعداد حسابك عبر `gcloud auth application-default login`؛ لا تضع مفتاح خدمة داخل الحزمة.

```powershell
Set-Location -LiteralPath (Join-Path $backendRoot 'functions')
& $nodeExe .\scripts\admin-backfill-lists.cjs --project=pharma-apps --apply
if ($LASTEXITCODE -ne 0) { throw 'توقفت تهيئة القوائم؛ أصلح الخطأ ثم أعد الأمر' }
```

النتيجة المطلوبة: اكتمال `requests`, `pharmacies`, `users`, `orders`, `notifications`, `audit`، ووجود `ready: true` و`schemaVersion: 1` في وثائق `adminLists` الست. نقص التهيئة يعرض خطأ واضحًا؛ لا تعتبره قائمة فارغة ناجحة.

### 5. تفعيل قواعد Firestore وإزالة الوظيفة القديمة

```powershell
Set-Location -LiteralPath $backendRoot
& $nodeExe $firebaseCli deploy --only firestore:rules --project pharma-apps
if ($LASTEXITCODE -ne 0) { throw 'توقف نشر القواعد' }
& $nodeExe $firebaseCli functions:list --project pharma-apps
```

إذا ظهرت `createAdminEmployee` في القائمة، نفّذ حذفها من المنطقة التي تظهر فيها (الافتراضية السابقة `us-central1`):

```powershell
& $nodeExe $firebaseCli functions:delete createAdminEmployee --region us-central1 --project pharma-apps
```

هذا لا يحذف حسابات المشرفين الموجودة. لا يتضمن تسليم الحد الأدنى تغيير قواعد Storage الحالية أو تطبيق الصيدلية.

### 6. تشغيل الواجهة وقبولها

```powershell
Set-Location -LiteralPath $adminRoot
& $nodeExe .\node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5173
```

افتح `http://127.0.0.1:5173`، وسجّل الدخول بحسابك. هذا التشغيل يتصل بالمشروع الحالي. بعد قبولك، ولتسليم الواجهة على الاستضافة الموجودة:

```powershell
Set-Location -LiteralPath $adminRoot
& $nodeExe .\node_modules\vite\bin\vite.js build
if ($LASTEXITCODE -ne 0) { throw 'فشل بناء نسخة الاستضافة' }
& $nodeExe $firebaseCli deploy --only hosting --project pharma-apps
```

## قائمة قبول الحد الأدنى

كل صف شرط مستقل تنفذه أنت وتسجل نتيجته. لا توجد نتائج نجاح مفترضة. اختر السجلات التي تسمح بتعديلها؛ الإرسال والاعتماد والإخفاء إجراءات فعلية.

| المعرف | ما تقوم به | شرط القبول |
|---|---|---|
| MIN-01 | دخول بحساب إداري فعال ثم خروج وإعادة فتح رابط داخلي | الصفحات متاحة للمخول؛ بعد الخروج يرجع الدخول ولا تبقى تفاصيل الجلسة |
| MIN-02 | افتح طلب تسجيل ومستنديه ونسخه؛ نفذ قرارًا مع السبب | أحدث نسخة ظاهرة؛ مستندان صالحان مطلوبان للاعتماد؛ سبب الرفض أو الاستكمال مطلوب؛ القرار يظهر للصيدلية |
| MIN-03 | أعد إرسال نفس القرار عند انقطاع الرد، ثم جرّب قرارًا من نسخة قديمة | لا يتكرر الأثر؛ النسخة القديمة تُرفض ويطلب تحديث البيانات |
| MIN-04 | أخفِ صيدلية ثم أعد ظهورها | سبب وتأكيد وتدقيق؛ تتغير رؤيتها للمستخدم، ولا تتغير حالة استقبالها أو طلباتها السابقة |
| MIN-05 | ابحث عن سجل خارج أول صفحة؛ تنقل بين صفحات الطلبات والمستخدمين والصيدليات | البحث من كامل المصدر، 50 سجلًا كحد أقصى للصفحة، العدد مطابق للفلتر، ولا تكرار للسجلات الثابتة |
| MIN-06 | تابع طلبًا قبل وبعد بلوغ 24 ساعة معالجة مع فترات انتظار عرض جزئي | جميع فترات انتظار العرض مستبعدة؛ التأخر يظهر عند الحد؛ يبقى سجله بعد الجاهزية |
| MIN-07 | تابع طلبًا جاهزًا عند بلوغ 24 ساعة من أول جاهزية ثم بعد استلامه | تأخر استلام مستقل؛ لا إلغاء آلي؛ يبقى التاريخ بعد إنهاء الطلب؛ الطلب للقراءة فقط في الإدارة |
| MIN-08 | افتح التنبيهات وفلاترها وروابط الطلب أو الصيدلية | تأخرا الصيدلية والمستخدم منفصلان؛ الرابط يفتح المصدر الصحيح؛ المنتهي يبقى في السجل |
| MIN-09 | افتح الخريطة وغيّر فلاترها | لا تُعرض إحداثيات غير صالحة؛ الأعداد تطابق القائمة؛ يمكن استخدام القائمة عند فشل الخرائط |
| MIN-10 | قارن الرئيسية والتقارير بمجاميع المصدر لفترة تختارها | كل الفترة محتسبة، بما فيها الأيام الخالية؛ نسب الإكمال والإلغاء صحيحة؛ البيانات المفقودة واضحة |
| MIN-11 | أرسل إشعارًا بفئة تختارها، راقب النتيجة، وأعد المتعثرين | تأكيد قبل الإرسال؛ عنوان ≤80 ونص ≤500؛ الأعداد مسجلة؛ إعادة المتعثرين لا تعيد الناجحين؛ لا يساوي نجاح FCM قراءة المستخدم |
| MIN-12 | راجع التدقيق للقرار والإخفاء والإشعار وقارن القائمة الجانبية بالنطاق | المنفذ والوقت والسبب وقبل/بعد ظاهرون؛ عشر وجهات معتمدة فقط؛ الوظائف المحذوفة غير متاحة |

يمكن تسجيل النتيجة بصيغة: `MIN-04: نجح/فشل — وصف ما ظهر`. عند نقص السجلات اللازمة لحالة ما تسجل «لم يُختبر»، ولا تسجل نجاحًا.

## المؤجل والحدود العملية

- التقارير تجمع البيانات خادميًا عند الطلب؛ لم تُنفذ المجاميع التراكمية ولا يثبت لها زمن استجابة أو تحمل أحمال قبل قياسك.
- إبطال روابط تنزيل المستندات القديمة، تضييق حماية Storage، وتغيير رفع المستندات في تطبيق الصيدلية مؤجلة. معاينة المستندات في الواجهة تستخدم جلسة الحساب؛ هذا لا يبطل رابطًا دائمًا قديمًا.
- بقيت شروط الحماية الشاملة، الوصولية والأداء والتوافق في الخطة الكاملة؛ لا تُعتبر مغلقة بتسليم الوظائف الدنيا.
- سجل التأخر القديم يعتمد على الحقول والتاريخ المتوفرين؛ البيانات غير المسجلة لا يمكن استعادتها بالتخمين.
- الإشعارات تستخدم معرفًا ثابتًا وسجل مستلم واستعادة للمعالجة المتوقفة. لا تُدّعى ضمانة نقل FCM مرة واحدة تمامًا عند ضياع إقرار مزود الخدمة.

يمكن اعتماد **الحد الأدنى الوظيفي** بعد تفعيل الخلفية والفهارس والقوائم، ونجاح قبولك أعلاه. لا توجد حاليًا شهادة مطابقة 100% أو إغلاق نهائي للتوثيق.
